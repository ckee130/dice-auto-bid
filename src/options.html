Dice Apply Bot

Everything here is stored on this machine only.

Dice job links

The only input a run needs. Paste Dice job pages - https://www.dice.com/job-detail/... - one per line, in the order you want them sent. Each is opened on Dice and read; where the posting takes Easy Apply, a resume and cover letter are written for it and the three steps of Dice's application are filled and submitted. A posting that applies on the company's own site is listed on the day's other links.csv and left alone.

Sign in to Dice in this browser first, as the applicant. The application form is behind the account; a run that finds the sign-in page stops and says so.

Repeats are applied to once. Anything that is not a Dice job link is reported and dropped.

A run works through exactly the list loaded here. Load it again after pasting more.

    Writing the application

    This is the full system prompt used to create resume content. It initially shows the current built-in prompt; edit it to replace that prompt for future resumes.

    The bot writes each resume and cover letter itself, with the same code the app uses. One provider and one key write both, and answer any screener question the settings below cannot. The key filled in is the team's Anthropic key; replace it to spend from another account.

    Each application costs one call for the resume (two or three if a draft breaks a rule and is repaired), one for the letter, and one per screener question the settings cannot answer. The log says after each what it cost.

    Simulate and preview a resume

    Paste a job description to generate the exact resume PDF a real run would attach. This makes one resume model call, opens the PDF for inspection, and does not visit Dice, create a cover letter, or submit anything.

    What every resume is built on

    The employers are yours. Unlike the other apply bots, the companies on this resume are not chosen by the model: each job row below names the company and the months it ran, and the resume carries exactly those, in that order. The model writes only the title and the bullets under each, tailored to the posting, and the summary and skills above them.

    Jobs

    Newest first. Company name and location as they should print, then the months it ran; leave "to" empty for a job still held. A row without a company is left out of the resume.

    Who is applying

    Printed on the resume and typed into the form exactly as written. Nothing here is generated.

    Everything a day produces goes to Downloads/job applied-folder/<day>/<profile name>/. Two browsers on one machine share one Downloads; give each its own name here.

    Dice asks for the city of residence on most applications and offers a list of "City, ST, USA" entries; the city and state here are what is typed to find yours.

    The questions Dice and its employers ask

    Dice itself asks for work authorization and the city of residence; both come from here. An employer may add screener questions of its own - these answers cover the usual ones, and the model answers the rest from the resume written for the posting and the facts below.

    Telling you in Slack

    An application this bot fills but cannot send is left open in its tab as it stands, with the files attached and the answers typed, for you to finish. With a bot token and a channel here, each one is announced there, and one more message when the run ends says what went and what is waiting. Leave both blank to send nothing.

    How the run behaves

    A submitted Dice application cannot be withdrawn. The first real run is worth capping.

    Settings backup

    Save every setting, including job history, the resume prompt, and the API and Slack keys, to a JSON file. Keep the file private because its keys are stored as readable text.
